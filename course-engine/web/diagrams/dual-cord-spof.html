Dual-cord SPOF — find the shared node

Run a real failure scenario against a dual-path facility and classify what actually happened. Interview one-liner: two cords are not two paths — every large public power postmortem turns on a node the one-line diagram does not draw.

The antecedent, stated once and carried everywhere. "Tolerates one failure" means one INDEPENDENT failure, from the normal operating state. A common-cause failure needs two ingredients: a failure cause, and a coupling factor that lets that cause reach several components at once. Almost every public incident where redundancy "failed" is a violation of the antecedent, not a counterexample to N+1 or 2N — and confusing the two drives the wrong spend (more modules) instead of the right one (independent controls, separated enclosures, decorrelated demand).

The classifier — nine coupling mechanisms

Common-cause failure analysis is mature, openly published, and largely absent from data-centre training — which is why common-mode events keep getting reported as "redundancy failed". When you study an outage, name the coupling before you name a fix.

  • design — identical modules, identical firmware, the same defect in both.
  • hardware — same manufacturer, rating and batch across the redundant group.
  • function — one command starts both; a shared start signal is a shared failure.
  • installation — both paths commissioned by the same crew, with the same error.
  • maintenance — the same procedure, applied to both sides, in the same window.
  • procedures — one wrong step in one runbook reaches every unit that runbook governs.
  • interfaces — the control plane, the network between controllers, the permissives.
  • locations — one room, one riser, one conduit, one shared proven pathway.
  • environment — the utility transient, the heat, the flood, the smoke.

The practical output. Draw a second diagram — the control-dependency graph — and require it at design review with the same seriousness as the one-line. Chiller controllers, paralleling boards, source synchronisers, ATS logic, BMS sequences, fuel control panels and EPO circuits are shared by construction and invisible on a power one-line. Every incident on this page turns on one of them.
